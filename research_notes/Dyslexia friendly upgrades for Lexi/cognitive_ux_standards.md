# Cognitive-accessibility UX standards and patterns for a dyslexia-first, emoji-first journaling chatbot ("Lexi")

Evidence-class tags used below: **[STANDARD]** = W3C/government/standards-body text; **[EVIDENCE]** = peer-reviewed or empirical study (sample size noted where known); **[PRACTICE]** = practitioner/government style guidance without cited trials; **[OPINION]** = blog, vendor, essay, anecdote. "Secondary" = I could not retrieve the primary text and am relying on a search snippet or a summary page. Lexi facts (3 tabs, emoji tiles, 👍🏽/👎🏽 pills, words-only mode, AI replies of 1-3 short sentences) come from the assignment brief only; I did not inspect the Lexi codebase, so "gap" statements are inferences from that description.

Research was run on 2026-10-17. Several fetches failed or returned partial text; those are flagged in the Gaps lists.

## 1. W3C COGA "Making Content Usable for People with Cognitive and Learning Disabilities": which objectives and patterns apply most?

### Takeaway
COGA (a W3C Working Group Note, supplemental to WCAG, not a Recommendation) has 8 objectives and ~60 numbered patterns. For a dyslexia-first chatbot the highest-yield ones are Obj. 3 (clear content), Obj. 4 (avoid mistakes/let users go back/avoid timeouts), Obj. 5 (focus/limit interruptions), Obj. 6 (don't rely on memory), Obj. 8 (personalization/simplification), plus the icon, emoji and symbol patterns in Obj. 1 and 3. Lexi's 3-tab structure already matches COGA's own "3 to 6 functions" simplicity yardstick.

### Cited Findings
- **Status [STANDARD]:** Working Group Note published 29 April 2021 by the Cognitive and Learning Disabilities Accessibility Task Force (Coga TF); supplemental guidance beyond WCAG 2.2, not required for conformance, not endorsed as a Recommendation. — [W3C COGA](https://www.w3.org/TR/coga-usable/)
- **The 8 objectives [STANDARD]:** (1) Help users understand what things are and how to use them (4.2); (2) Help users find what they need (4.3); (3) Use clear and understandable content (4.4); (4) Help users avoid mistakes and know how to correct them (4.5); (5) Help users focus (4.6); (6) Ensure processes do not rely on memory (4.7); (7) Provide help and support (4.8); (8) Support adaptation and personalization (4.9). Testing with real users is Section 5. — [W3C COGA](https://www.w3.org/TR/coga-usable/)
- **Clear words (4.4.1) [STANDARD]:** use common words; the guide points to the most common 1,500 words/phrases as a reference; remove vague filler; explain or remove jargon/acronyms; do not give words new meanings; explain any new term within one click; start with headings, labels, navigation, instructions and error messages. — [W3C COGA 4.4.1](https://www.w3.org/TR/coga-usable/)
- **Other language patterns (4.4.2-4.4.4) [STANDARD]:** simple tense and voice; avoid double negatives and nested clauses; use literal language. — [W3C COGA](https://www.w3.org/TR/coga-usable/)
- **Chunking / succinct text (4.4.5, 4.4.9, 4.4.10, 4.3.5, 4.6.3) [STANDARD]:** short paragraphs, one topic each, aim stated first, short sentences with one point each; in English split any paragraph over 50 words; bulleted list for 3+ items, numbered list for 3+ steps; separate each instruction; use white space ("white space" means background colour, need not be white) but not so much that key content falls below the scroll; usability-test whether a long sentence is clearer than two short ones. — [W3C COGA 4.4.5, 4.4.10](https://www.w3.org/TR/coga-usable/)
- **Implied content incl. emoji (4.4.12) [STANDARD]:** explain implied/ambiguous content (gestures, emotions, jokes, sarcasm, metaphors, facial expressions) in nearby text or markup; one cited study found autistic participants missed sarcasm conveyed through facial expressions; guidance says "Standard emojis often come with an explanation." — [W3C COGA 4.4.12](https://www.w3.org/TR/coga-usable/)
- **Icons (4.2.7) [STANDARD]:** add familiar icons to important controls and headings; "each icon should have one meaning" and sit next to the content it relates to; icons help people with language, learning or reading difficulties and act as signposts for people who find dense text hard to scan; use clear, easy-to-see, enlargeable icons; watch cultural differences; avoid clutter; in LTR languages put a few icons to the left of text. — [W3C COGA 4.2.7](https://www.w3.org/TR/coga-usable/)
- **Clearly identify controls (4.2.5) [STANDARD]:** make controls recognisable (visible borders, standard styles), make click targets large enough to avoid hitting the neighbour, don't make non-clickable things look like controls; unusual controls get instructions on the same page. — [W3C COGA 4.2.5](https://www.w3.org/TR/coga-usable/)
- **Consistency (4.2.2, 4.2.3) [STANDARD]:** familiar hierarchy/layout and a consistent visual design across screens. — [W3C COGA](https://www.w3.org/TR/coga-usable/)
- **Controls and content must not move unexpectedly (4.5.1) and users can go back (4.5.2) [STANDARD]:** back must work predictably and "never delete a user's work when they go back"; re-entering data is stressful and error-prone; some users prefer to follow directions and review answers as separate tasks. — [W3C COGA 4.5.2](https://www.w3.org/TR/coga-usable/)
- **Undo / error prevention (4.5.4, 4.5.5, 4.5.8, 4.8.3) [STANDARD]:** design to prevent mistakes; make errors easy to undo; accept different input formats; state results and disadvantages of actions next to each option and ask users to confirm unexpected changes. — [W3C COGA](https://www.w3.org/TR/coga-usable/) (4.5.4/4.5.5/4.5.8 detail text not read; titles only)
- **Avoid data loss and timeouts (4.5.9) [STANDARD]:** avoid timeouts and let users save as they go; if unavoidable, say at the start how much time they have and whether data will be lost; users need time to look things up, take breaks and recover from fatigue. — [W3C COGA 4.5.9](https://www.w3.org/TR/coga-usable/)
- **Feedback (4.5.10) [STANDARD]:** tell users the status of each step and whether it succeeded; examples include checkmarks on completed steps, pressed states, and confirmations like "Your email message was sent." — [W3C COGA 4.5.10](https://www.w3.org/TR/coga-usable/)
- **Limit interruptions (4.6.1) and short critical paths (4.6.2) [STANDARD]:** let users control reminders/moving content/sounds; offer a pause option and notification settings (visual, sound, none); avoid pop-ups that must be closed; keep processes to necessary steps and separate optional ones. — [W3C COGA 4.6.1-4.6.2](https://www.w3.org/TR/coga-usable/)
- **No reliance on memory (4.7.5) [STANDARD]:** don't require remembering digits, calculating, copying or recalling across steps; "each step should contain the information needed to proceed"; provide a summary of prior steps, a step indicator, an easy way back, and error fixes rather than full restarts. — [W3C COGA 4.7.5](https://www.w3.org/TR/coga-usable/)
- **Reminders (4.8.7) [STANDARD]:** set reminders only at the user's request, let users personalise the method, offer at the end of a task rather than interrupting. — [W3C COGA 4.8.7](https://www.w3.org/TR/coga-usable/)
- **Help (4.8.1, 4.8.5) [STANDARD]:** "provide human help" and "make it easy to find help and give feedback" are listed patterns (detail text not read). — [W3C COGA TOC](https://www.w3.org/TR/coga-usable/)
- **Let users control change (4.9.1) [STANDARD]:** changes to context, functionality, settings, route and orientation should happen only on user request or be easy to turn off; examples of harm include automatic pop-ups, unlabeled submission, unexpected option changes. "Easily available" means set once with widest scope, savable per page set, or reachable from every screen where needed. — [W3C COGA 4.9.1](https://www.w3.org/TR/coga-usable/)
- **Simplification (4.9.3) [STANDARD]:** hide non-essential features, offer less or simpler text, let users reveal extras when wanted; "Typically, a simple application has 3 to 6 functions." — [W3C COGA 4.9.3](https://www.w3.org/TR/coga-usable/)
- **Personalized and familiar interface (4.9.4) [STANDARD]:** users can set font style, size, line height, margins, contrast; default must stay readable; users can roll back to a familiar interface; AAC users often learn only one symbol set and struggle when apps use different symbols, so personalization lets the user agent load symbols the individual understands; non-sensitive info can be stored to ease form filling. — [W3C COGA 4.9.4](https://www.w3.org/TR/coga-usable/)
- **Persona evidence on emoji/TTS [STANDARD, persona-level not empirical]:** a persona (George) finds that "the way emojis change or new icons keep appearing on his message systems rather confusing"; COGA calls for text-to-speech with synchronized highlighting (4.9.2.3); one persona finds synthesized speech distracting and another cannot speed up TTS, i.e. TTS preferences vary. — [W3C COGA 6.3.2, 4.9.2](https://www.w3.org/TR/coga-usable/)
- **GOV.UK dyslexia checklist (2016) [PRACTICE]:** for dyslexia "Do": images and diagrams to support text; left-align; consistent layout; other formats (audio/video); short clear simple content; let users change contrast. "Don't": large blocks of heavy text; underline, italicise or capitalise words; make users remember details from earlier pages (give reminders/prompts); rely on accurate spelling (offer autocorrect/suggestions); too much information in one place. For autism: descriptive buttons ("Attach files"), avoid "Click here", avoid figures of speech/idioms, avoid walls of text. — [GOV.UK Home Office Digital accessibility blog, 2 Sep 2016](https://accessibility.blog.gov.uk/2016/09/02/dos-and-donts-on-designing-for-accessibility/)

### Inferences
- Priority COGA patterns for Lexi, in order: 4.4.1-4.4.5 (bubble wording), 4.2.7 + 4.4.12 + 4.9.4 (emoji/icon meaning and personalization), 4.5.1/4.5.2/4.5.5/4.5.9 (stability, back, undo, save), 4.6.1 + 4.9.1 (user-controlled pacing/notifications), 4.7.5 (progress + recap in check-ins), 4.8.5 (visible help), 4.9.3/4.9.4 (words-only, text settings).
- Lexi's 3-tab nav (Settings/Home/Journal) is consistent with COGA 4.9.3's "3 to 6 functions" yardstick; keep new features inside Home/Journal rather than adding tabs.
- "One meaning per icon" (4.2.7) is the single most checkable rule for the emoji tiles and 👍🏽/👎🏽: audit for any tile whose emoji can plausibly be read two ways.
- GOV.UK's "don't rely on accurate spelling" is directly relevant to free-text input in a dyslexia-first app: free text must tolerate misspellings and AI parsing must not penalise them.

### Gaps
- I read COGA's text only through the 4.9.x range (about 400k of 470k characters); detail for 4.2.4 (make each step clear), 4.5.4/4.5.5/4.5.8, 4.5.11 (Help the user stay safe), 4.8.1, 4.8.5 and Section 5 was not read. COGA (2021 Note) contains no dedicated conversational-UI/chatbot section in the portions I read.
- The GOV.UK dyslexia poster itself was not retrieved; the blog post text above is the primary summary of it. A dated GOV.UK/NHS design-system page on dyslexia was not found in the time available.

## 2. WCAG 2.2 cognition-related criteria, and draft WCAG 3 / plain-language guidance

### Takeaway
WCAG 2.2 added three cognition-relevant criteria (3.2.6 Consistent Help A, 3.3.7 Redundant Entry A, 3.3.8 Accessible Authentication Minimum AA) and keeps older timing/spacing/labels criteria (2.2.1, 2.2.6, 1.4.12, 2.4.6, 3.1.5). WCAG 3.0 remains a non-final Working Draft whose outcome-based requirements include "Clear language," "Adequate time," "Prevent errors," "Help available" and "Consistency," but with text-spacing values still "to be determined."

### Cited Findings
- **3.2.6 Consistent Help (Level A) [STANDARD]:** if help mechanisms (contact details, human or automated contact, self-help) repeat across pages they appear in the same relative order unless the user changes it. — [W3C What's new in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
- **3.3.7 Redundant Entry (A) [STANDARD]:** information already entered in the same process must be auto-populated or selectable unless re-entry is essential, a security need, or no longer valid; stated benefit: some people with cognitive disabilities have difficulty remembering what they entered earlier. — [W3C What's new in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
- **3.3.8 Accessible Authentication (Minimum) (AA); 3.3.9 Enhanced (AAA) [STANDARD]:** login cannot require a cognitive function test (memorising, puzzles, transcribing) unless an alternative, assistance mechanism, or object-recognition/personal-content option exists. — [W3C What's new in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
- **Level conflict note:** one third-party blog lists several of these at wrong levels (e.g., 3.2.6 as AAA); the W3C page above gives 3.2.6 A, 3.3.7 A, 3.3.8 AA, 3.3.9 AAA. — contradicts [TestParty summary via search](https://testparty.ai/blog/wcag-22-new-success-criteria)
- **2.5.8 Target Size (Minimum) (AA) [STANDARD]:** targets at least 24x24 CSS px or spaced; stated benefit is for motor impairments (no cognitive benefit stated). **2.4.11 Focus Not Obscured (AA)** and **2.5.7 Dragging Movements (AA)** are also new; 4.1.1 Parsing was removed. — [W3C What's new in WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
- **1.4.12 Text Spacing (AA) [STANDARD]:** content must remain readable/operable (no loss of content or function) when users override to line height >= 1.5x font size, paragraph spacing >= 2x, letter spacing >= 0.12x, word spacing >= 0.16x. It does not require authors to use those values. Benefit: people with dyslexia may increase spacing between lines, words and letters "to increase reading speed." Cited research: Rello & Baeza-Yates (2017); Sjoblom, Eaton & Stagg (2016); Zorzi et al. (2012, PNAS). — [W3C Understanding 1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)
- **2.2.1 Timing Adjustable (A) [STANDARD]:** for each content-set time limit the user can turn it off, adjust it (range at least 10x default), or extend it (warning plus at least 20 seconds to extend, extendable at least 10 times); exceptions: real-time events, essential limits, limits over 20 hours. Benefit: people with reading/cognitive/learning disabilities who need longer to read and understand. — [W3C Understanding 2.2.1](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html)
- **2.2.6 Timeouts (AAA) [STANDARD]:** warn users about inactivity duration that causes data loss unless data is preserved for more than 20 hours; best conformance route is to keep data at least 20 hours; benefits users with language, memory, attention and executive-function disabilities. — [W3C Understanding 2.2.6](https://www.w3.org/WAI/WCAG22/Understanding/timeouts.html)
- **2.4.6 Headings and Labels (AA) [STANDARD]:** headings and labels describe topic or purpose; "especially helpful for users who have disabilities that make reading slow" and for limited short-term memory. — [W3C Understanding 2.4.6](https://www.w3.org/WAI/WCAG22/Understanding/headings-and-labels.html)
- **3.1.5 Reading Level (AAA) [STANDARD]:** if text needs more than lower-secondary reading ability (about 7-9 years of school after 6 primary), provide supplemental content (summary, illustration, audio, sign) or a simpler version; rationale: in dyslexia decoding consumes mental energy otherwise available for comprehension. W3C admits the Working Group could not find a way to test clear writing directly, so reading level was used to make the criterion testable, and "Easy to Read can't be universal." — [W3C Understanding 3.1.5](https://www.w3.org/WAI/WCAG22/Understanding/reading-level.html)
- **WCAG 3.0 status [STANDARD, non-normative]:** the page at w3.org/TR/wcag-3.0/ was a Working Draft (fetched version dated 10 September 2026); "may be updated, replaced, or obsoleted at any time"; guidelines marked "Developing"; WCAG 2.2 is not deprecated. Structure: outcomes, core/supplemental requirements, assertions, methods. Dated earlier drafts exist (e.g., 2026-03-03). — [W3C WCAG 3.0 WD](https://www.w3.org/TR/wcag-3.0/), [20260303 WD](https://www.w3.org/TR/2026/WD-wcag-3.0-20260303/)
- **WCAG 3 draft contents relevant here [STANDARD draft]:** 2.2.3 Clear language (abbreviations explained, non-literal language explained, summaries available, common words, no nested clauses, no unnecessary words, review requirements); 2.9.1 avoid exclusionary cognitive tasks; 2.9.2 Adequate time (adjustable/no/avoid/convey time limits); 2.5.2 Prevent errors and 2.5.1 correcting errors; 2.11.1 Help available (consistent help, contextual help, explain disabled controls, help usability testing); 2.8.1 Consistency (structural order, navigation order, nav labels) and 2.3.4 consistent interactions/control locations; 2.2.1 text appearance (margins, line length, line height) with values "[values to be determined]"; 2.12.1 assistive tech/user settings support; no dedicated icon/symbol guideline appeared in the portion read. — [W3C WCAG 3.0 WD](https://www.w3.org/TR/wcag-3.0/)
- **Secondary commentary on WCAG 3 [OPINION/secondary]:** AbilityNet reports an in-development requirement on non-literal language (idioms, metaphors need explanation) helpful to autistic and ESL users; a third-party explainer reports ~174 outcomes and Bronze/Silver/Gold levels - **not confirmed** by the W3C text I fetched (the fetched text did not name those tiers). — [AbilityNet](https://abilitynet.org.uk/resources/digital-accessibility/what-expect-wcag-30-web-content-accessibility-guidelines)

### Inferences
- WCAG 2.2 is written for web content; Lexi's web app is in scope directly, and the React Native app is in scope only by analogy (mobile applicability is not covered by anything I fetched).
- **3.2.6:** Lexi should have one persistent help affordance (e.g., a "?" or "Need help?" chip) in the same place on every screen including inside check-ins; an automated chat mechanism counts as help if repeated across pages per the criterion wording, so the chat itself should not be the only help surface when the user is inside Journal/Settings.
- **3.3.7:** if check-ins re-ask something answered earlier in the session (mood, date, name), pre-fill or let user tap "same as before."
- **3.3.8:** if/when accounts exist, avoid password-only or typed one-time-code flows; allow paste/password managers, magic link or device biometrics.
- **1.4.12:** on the web app, test chat bubbles, tile captions and pills with the four spacing overrides (1.5 / 2 / 0.12 / 0.16) - no clipping or overlap. For native, expose letter/word/line spacing as an in-app setting because RN does not receive a browser override (inference; the Zorzi evidence in section 3 supports letter spacing as the highest-value dial).
- **2.2.x:** Lexi should have no time-limited UI at all (no auto-expiring quick replies); if a session timeout exists, preserve drafts well beyond 20 hours.
- WCAG 3 is a direction-setting reference only; do not cite it as a compliance requirement.

### Gaps
- Not fetched: WCAG 2.2 normative text for 2.2.2 (Pause, Stop, Hide), 3.1.3/3.1.4 (unusual words, abbreviations), 3.3.4 (error prevention), 2.4.3/2.4.5/2.4.10, 1.3.5 (Identify Input Purpose), 2.5.5 (AAA target size 44px), and contrast ratios. Of the 2.4.x family I verified only 2.4.6 and 2.4.11.
- WCAG 3 draft: I read only the first ~100k of ~373k characters; Bronze/Silver/Gold claims unconfirmed; no icon/symbol guideline seen. The 10 Sep 2026 draft date conflicts with a search result that treated the March 2026 draft as most recent; check the W3C TR history page.
- Applicability of WCAG to native mobile apps (WCAG2ICT / W3C mobile guidance) was not researched.

## 3. Plain language for dyslexic readers: sentence length, word frequency, readability formulas and limits, easy-read; GOV.UK / PLAIN / Inclusion Europe

### Takeaway
All major sources converge on short sentences, common words, one idea per sentence, left-aligned unjustified text and generous spacing, but the exact numeric limits (15-20 vs 25 words; 12-14 pt) are practice conventions, not trial-derived thresholds, and readability formulas measure surface features only. The strongest trial-based dyslexia typography result I found is extra-large letter spacing (Zorzi 2012); I found no verified evidence for "dyslexia fonts."

### Cited Findings
- **GOV.UK sentence length [PRACTICE]:** a 2014 Inside GOV.UK post said the style guide advised breaking up/condensing sentences over 25 words; the post is now flagged "may now be out of date," so the current figure is unverified. — [Inside GOV.UK 2014](https://insidegovuk.blog.gov.uk/2014/08/04/sentence-length-why-25-words-is-our-limit/)
- **Reading age ~9 and 15-20 word averages [PRACTICE, secondary]:** UK councils cite "aiming for a reading age of 9 … in line with GOV.UK standards" and cite the Plain English Campaign's suggested average sentence length of 15-20 words. — [Somerset Council playbook](https://playbook.somerset.gov.uk/digital-inclusion-and-accessibility/creating-accessible-documents/document-language-and-reading-age) and other council pages in search results
- **COGA numbers [STANDARD]:** 1,500 most common words as reference vocabulary; split English paragraphs over 50 words; lists for 3+ items/steps. — [W3C COGA 4.4.1, 4.4.5](https://www.w3.org/TR/coga-usable/)
- **Inclusion Europe "Information for all" (easy-to-read) [STANDARD-ish, voluntary; not EU law]:** created 2010 by partners in the "Pathways to adult education for people with intellectual disabilities" project; ~18 languages; page dated 6 Oct 2021; owners of the easy-to-read logo; a simplified checklist PDF exists. — [Inclusion Europe](https://www.inclusion-europe.eu/easy-to-read-standards-guidelines/); not adopted as EU law per a Polish government source summarised in search results.
- **Inclusion Europe rules as summarised by a secondary source [PRACTICE, secondary]:** everyday words; same word for same thing throughout; explain difficult words where they first appear (not in a glossary); avoid metaphors, abbreviations and percentages; numbers as digits; short sentences, one idea per sentence; active voice; address reader as "you"; don't split an idea across a line break; clear sans-serif, at least 14 pt in print and larger on screen; generous line spacing; left-align, never justify; one sentence per line where possible; avoid text over images, columns, italics, whole words in capitals; place supporting images next to the text they belong to; most important information first; "The text must be checked by people with intellectual disabilities before it is published." — [e-include.eu summary of the European standards](https://e-include.eu/easy-to-read/european-standards/)
- **BDA / dyslexia-friendly style guides [PRACTICE, secondary]:** 12-14 pt sans-serif (some readers need larger); headings at least ~20% larger than body, bold (not italics/underline) for emphasis; left-aligned, no justification, avoid centred/right-aligned; dark-not-black text on light-not-white background; avoid red/green combinations; use real formatting tools for spacing so assistive tech works. The BDA's own style-guide URL returned 404; this is from derivative guides. — [Ako Aotearoa dyslexia-friendly style guide](https://ako.ac.nz/assets/Knowledge-centre/ALNACC-Resources/Dyslexia-resources/230907-Dyslexia-Friendly-Style-Guide.pdf), [North Somerset summary of BDA Style Guide 2018](https://theaccessofficer.n-somerset.gov.uk/2019/08/01/dyslexia-style-guide-2018), [BDA creating dyslexia-friendly resources](https://bdadyslexia.org.uk/advice/educators/teaching-for-neurodiversity/creating-dyslexia-friendly-resources)
- **Letter spacing trial [EVIDENCE]:** Zorzi et al. 2012 (PNAS), dyslexic children aged 8-14: extra-large letter spacing (about +2.5 font-size units in the spaced condition per a press summary) roughly doubled reading accuracy and increased speed by over 20% in one press summary; benefit seen in dyslexic children, not in reading-level-matched typical readers; later adult study (Sjoblom et al. 2016) found evidence for spacing but contradictory evidence for coloured overlays. Authors defended the stats against a critique (reply to Skottun & Skoyles). — [Zorzi et al. 2012 PMC](https://pmc.ncbi.nlm.nih.gov/articles/PMC3497756), [ScienceDaily](https://sciencedaily.com/releases/2012/06/120607105712.htm), [Sjoblom et al. 2016](https://westminsterresearch.westminster.ac.uk/item/x14x1/the-effects-of-letter-spacing-and-coloured-overlays-on-reading-speed-and-accuracy-in-adult-dyslexia) (the numbers above are from press/aggregator summaries, not re-read from the paper)
- **Readability formulas and their limits [PRACTICE/STANDARD]:** Flesch Reading Ease and Flesch-Kincaid score semantic and syntactic surface features only; ignore prior knowledge, motivation, purpose; same formula can give different scores in different tools; pictures/tables not accounted for; grade level "often interpreted … in ways that go well beyond what they measure." — [AHRQ Tip 6](https://www.ahrq.gov/talkingquality/resources/writing/tip6.html), [readabilityformulas.com](https://readabilityformulas.com/articles/readability-formulas-and-grade-level-scores.php)
- **W3C on measurability [STANDARD]:** WCAG 3.1.5 uses reading level because the WG could not find a way to test clear writing directly; short, common words/sentences are easier to decode, "a general guide, not a full measure of understanding." — [W3C Understanding 3.1.5](https://www.w3.org/WAI/WCAG22/Understanding/reading-level.html)
- **Digital.gov / Plain Writing Act:** the US plain-language guide states the Plain Writing Act of 2010 requires public content be written for its specific audience; the page fetched did not state sentence-length numbers. — [Digital.gov plain language guide](https://digital.gov/guides/plain-language)

### Inferences
- A defensible, checkable Lexi bubble rule: <= ~15-20 words average and a hard cap of 25 per sentence; <= 50 words per bubble (COGA's paragraph rule); one idea per sentence; active voice; no idioms/metaphors; same word for the same thing everywhere (e.g., always "check-in," never alternate with "session"). Treat the numbers as guidelines (practice-based), enforce with an automated linter on both scripted copy and AI output, and verify with dyslexic users (Inclusion Europe stresses testing with the target group; their rule names people with intellectual disabilities, not dyslexia specifically).
- Use readability formulas only as a smoke test for scripted copy; do not rely on them to certify AI replies, since the formulas ignore vocabulary familiarity and context. A word-frequency check against a common-word list (COGA's ~1,500 words reference) is a more relevant lint for dyslexic readers, though COGA's exact list was not retrieved.
- Typography dials with the best support for dyslexia are letter-spacing and line/word spacing (WCAG 1.4.12 plus Zorzi), left alignment, sans-serif, and avoiding italics/caps/underline; give users these as settings (see section 7).

### Gaps
- Primary text of the Inclusion Europe PDF could not be parsed (the PDF I fetched was a one-page leaflet); rules above are via a secondary summary. Line length and list rules from the standard were not retrieved.
- GOV.UK's current official plain-English page (e.g., "use clear language") returned 404/redirects; the 25-word limit and reading-age-9 are therefore dated or secondary. No verified GOV.UK statement on "most users including specialists prefer plain English" was retrieved.
- PLAIN/plainlanguage.gov (now digital.gov) sentence-length evidence not retrieved; its migrated page had no numbers.
- No verified evidence either way on dyslexia-specific fonts (e.g., OpenDyslexic/Dyslexie), line length for dyslexic readers, or background colour; the search for the Wery & Diliberto-type font studies returned nothing relevant. Treat font-as-cure claims as unverified.
- Word-frequency thresholds specific to dyslexic readers: no source found.

## 4. Icons, emoji and pictograms: comprehension for dyslexia/low literacy, emoji ambiguity, pairing icons with labels

### Takeaway
Authoritative guidance (NN/g, COGA, DOT human-factors review) says icons should always be paired with visible text labels and should carry one meaning; empirical evidence specifically that emoji or icons improve comprehension for dyslexic readers is thin and mixed, and emoji interpretation varies across people and platforms (about 25% sentiment disagreement even for the same rendering). Lexi's tile+caption design and words-only mode are well aligned; the weak points to audit are ambiguous glyphs (👍🏽/👎🏽, 🏡, ⚙️/📖 mappings) and decorative emoji inside sentences.

### Cited Findings
- **NN/g "Icon Usability" (Aurora Harley, 27 Jul 2014) [PRACTICE/expert-review, small studies]:** most icons lack a standard meaning so a text label should accompany the icon; labels should be visible at all times (hover-only labels add interaction cost and fail on touch); labels matter even for standard icons; only home, print and magnifying glass cited as near-universal; heart and star often misread; "5-second rule" (if you can't think of the icon in five seconds it probably won't communicate); test recognisability and test memorability after a couple of weeks; "Always include a visible text label." Evidence is mostly observations from small usability studies without reported sample sizes. — [NN/g](https://www.nngroup.com/articles/icon-usability/)
- **NN/g video summary [PRACTICE]:** "Due to the absence of a standard usage for most icons, text labels are necessary." — [NN/g](https://www.nngroup.com/videos/icon-usability/)
- **US DOT/FHWA human-factors review [EVIDENCE, older]:** icons paired with text labels enhance performance versus icons alone; labels should be concise (2-3 words) and used sparingly (as reported in search snippet; page not read in full). — [FHWA](https://www.fhwa.dot.gov/publications/research/safety/03065/05.cfm)
- **COGA [STANDARD]:** icons help language/learning/reading difficulties, one meaning each, next to related content; emoji need explanation; personal symbol sets matter for AAC users. — [W3C COGA 4.2.7, 4.4.12, 4.9.4](https://www.w3.org/TR/coga-usable/)
- **Inclusion Europe easy-read [PRACTICE, secondary]:** supporting images placed next to the text they belong to. — [e-include.eu](https://e-include.eu/easy-to-read/european-standards/)
- **GOV.UK 2016 [PRACTICE]:** for dyslexia, use images and diagrams to support text; for autism avoid figures of speech/idioms. — [GOV.UK a11y blog](https://accessibility.blog.gov.uk/2016/09/02/dos-and-donts-on-designing-for-accessibility/)
- **Emoticons and dyslexic youth [EVIDENCE, preliminary]:** Leśniak & Grzybowski (2021), 16 dyslexic pupils aged 11-15 vs 16 controls reading short messages with and without emoticons; the dyslexic group answered more slowly across all message types; authors label it a preliminary study. I could not retrieve the full text (PMC blocked); details are from a search summary. — [PMC8374149](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC8374149/)
- **Pictures/pictograms with dyslexic readers [EVIDENCE, small/adjacent]:** Sawander (2017) eye-tracking with 10 dyslexic and 14 non-dyslexic readers on pictures in digital learning material (illustrations, not emoji); a driving-simulator study with 22 adults with dyslexia and 22 controls found dyslexic participants began reading text messages closer to the sign, and the authors describe pictograms as a "controversial countermeasure." These come from search-result summaries only; the specific numbers could not be pinned to a single URL, so treat as unverified. — candidate sources listed in the search results (none read): [Kyushu University design topic page](https://www.design.kyushu-u.ac.jp/en/topics/15611/), [fitforthem.unipa.it pictogram subject page](https://fitforthem.unipa.it/subject:Pictogram), [Linköping emoji report](https://www.ida.liu.se/~arnjo82/diginclude/Rapporter/Emojirapport.pdf)
- **General emoji processing cost [EVIDENCE, non-dyslexic]:** a separate study (via search summary) found emoji add a small processing cost for typical readers - image interpreted first, then word inferred. — [Technology Networks summary](https://www.technologynetworks.com/neuroscience/news/exploring-how-we-understand-emoji-355807)
- **Emoji ambiguity [EVIDENCE]:** Miller et al. (ICWSM 2016, GroupLens), online survey of popular emoji rendered across platforms: participants disagreed on whether the same rendering was positive, neutral or negative 25% of the time, and disagreement increased across platform renderings. Morstatter et al. (2017) confirm cross-platform sentiment differences with Twitter data. — [Miller et al. 2016](https://ojs.aaai.org/index.php/ICWSM/article/view/14757), [Morstatter et al. 2017](https://arxiv.org/pdf/1709.04969)
- **AAC symbol research [EVIDENCE, background]:** iconicity is a continuum from transparent (guessable) to opaque; Bloomberg, Karlan & Lloyd (1990) rated five symbol systems and found transparency varied across systems and word classes (Rebus and PCS most transparent), cautioning against generalising to young/impaired learners; a 2019 Korean-American study found culture affects graphic-symbol recognition; a 2026 review of six experimental studies reports transparency aids initial recognition and translucency signals mediated learning (abstract only). I did not find research directly testing symbol+text pairing for dyslexic adults. — [Bloomberg et al. 1990 (unofficial Scribd copy)](https://www.scribd.com/document/86187253/2003), [e-csd.org (2019 Korea-US study listing)](https://e-csd.org/journal/view.php?number=913)
- **Apple Assistive Access (iOS 17) [PRACTICE]:** a system-level interface for cognitive disability with high-contrast buttons, large text labels, and a choice of grid layout (large icons) or row layout (bigger labels) - i.e., Apple offers both icon-led and label-led modes. — [Perkins School](https://www.perkins.org/resource/apple-unveils-new-features-for-global-accessibility-awareness-day/) (secondary; Apple developer docs not read)

### Inferences
- Lexi's emoji tiles with word captions meet NN/g and COGA's "always visible label" advice; verify the label is visible in every mode (tab bar, tiles, pills) and never in a tooltip/long-press.
- 👍🏽/👎🏽 risk: thumbs mean "like/dislike" on most platforms, so on a negative-valence question ("Did you feel worried?") 👎 reads as "I didn't" or "bad" ambiguously; this is a double-negative/valence trap (COGA 4.4.3). Mitigation: always render the words "Yes"/"No" on the pill (or use only words), and phrase questions so "Yes" = the plain affirmative. Skin-tone modifiers are a personalization choice; consider making the tone user-selectable or default neutral (inference; no source on this).
- Tab bar: ⚙️ for Settings is conventional; "🏡 Home (chat)" mixes a non-standard house glyph with a label ("Home") that actually means chat; "📖 Journal" may be read as "book/read/story." NN/g's 5-second and recognisability/memorability tests (ask users what each icon means; recheck after ~2 weeks) are cheap checks. Treat these as hypotheses to test, not established defects.
- Emoji rendering varies by OS (Miller 2016); Lexi's web and RN versions will render differently. Prefer a bundled, fixed emoji/illustration set for tiles (inference) so the same tile looks identical on every device; or let users pick a symbol set (COGA 4.9.4).
- Don't scatter emoji mid-sentence in bubbles; place at end or start, keep to a stated rule, and make sure the AI's replies obey it. Text-to-speech users (COGA personas) may have emoji read aloud as long descriptions (not verified here) - test with VoiceOver/TalkBack.
- Because dyslexic-specific emoji evidence is weak and slower response was observed in the one preliminary study, treat emoji as a supplement to words rather than the sole carrier of meaning, and keep words-only mode first-class (it satisfies COGA 4.9.3/4.9.4 simplification/personalization).

### Gaps
- No large or peer-reviewed study of emoji or icon-plus-label comprehension in adult dyslexic users was found; the dyslexic studies above are small, preliminary or adjacent (roadside signs, learning illustrations).
- The dyslexia-emoji study details are from search snippets (PMC and PubMed blocked fetch).
- No source retrieved on emoji text-to-speech verbosity, skin-tone modifier effects, or optimal emoji count per message.
- AAC research on symbol-plus-written-word pairing was not found; AAC citations are background.

## 5. Conversational UI / chatbot design for neurodivergent users: pacing, typing indicators, user-controlled speed, walls of text, quick replies vs free text, memory, undo/edit

### Takeaway
There is little direct empirical research on chatbot pacing or quick-reply design for dyslexic or neurodivergent users; the actionable guidance comes by transfer from COGA/WCAG (user-controlled change, no unexpected movement, undo, no memory demands, tolerate misspelling) plus a small HCI literature showing neurodivergent adults use chatbots for working-memory and emotional-regulation support and flagging over-trust and masking risks.

### Cited Findings
- **CHI 2026 short paper [EVIDENCE, qualitative]:** Giri, Brady & Marathe, 23 semi-structured interviews with neurodivergent adults (ADHD, autism, social anxiety, OCD and others; skews young and tech-literate). Uses: emotional regulation (summarising emotionally charged messages to avoid dysregulation) and working-memory support (summarising long texts). Tensions: authenticity, privacy, effects on relationships, reinforcement of neurotypical norms/masking. — [aggregator listing](https://a11y-paradise.onrender.com/reviews/69e7bddb5ba37b5ea06cce97) (DOI cited in search: 10.1145/3772318.3791334; full text not read)
- **Scoping review [EVIDENCE, secondary studies]:** Xu et al. (2025), 117 peer-reviewed papers on autism, ADHD and dyslexia; multimodal interaction, adaptive feedback and embodied interfaces enhance engagement/usability; most studies lack neurodivergent user participation. — [Heriot-Watt portal](https://researchportal.hw.ac.uk/en/publications/a-scoping-review-of-inclusive-and-adaptive-humanai-interaction-de/)
- **Autistic adults and a conversational agent [EVIDENCE, small]:** Xygkou et al., 6 autistic and 6 non-autistic adults over 1-4 weeks with the Kuki chatbot; autistic participants expected more in-depth conversation and empathy; no sign of relationship development. — [Xygkou publications page](https://kent.academia.edu/AnnaKsigou) (abstract-level; not read in full)
- **Disability chatbot use [EVIDENCE, qualitative, aggregator]:** interview study of people with disabilities (incl. autistic/ADHD participants) found nine use categories (a "diary"-like use is noted in the title) and concerns about over-trust, e.g., for companionship and medical advice. — [aggregator listing](https://a11y-paradise.onrender.com/reviews/69ae2a204becc40cc8e499f0)
- **Autistic users and ChatGPT [EVIDENCE, social-media analysis]:** a 3,984-post analysis reports emotional regulation and identity validation benefits alongside risks (reinforcing delusional thinking, erasing authentic identity through automated masking). — [arXiv 2601.17946](https://arxiv.org/html/2601.17946v1) (as summarised in search results)
- **Response delay and typing indicators [EVIDENCE, general population]:** Gnewuch et al. (ECIS 2018) found dynamic response delays increase perceived humanness and social presence and satisfaction, while noting delays can reduce satisfaction where speed is expected (e.g., customer service); a 2022 BISE follow-up on moderating role of prior experience exists (findings not read). Vendor docs describe typing indicators as human-like (marketing, not evidence). — [Gnewuch et al. 2018](https://aisel.aisnet.org/ecis2018_rp/113/)
- **Transferable standards [STANDARD]:** changes to content/context only on user request (COGA 4.9.1); controls/content must not move unexpectedly (4.5.1); limit interruptions with pause and notification settings (4.6.1); tell users the status of each step (4.5.10); undo errors (4.5.5) and go back without losing work (4.5.2); accept varied input formats (4.5.8); avoid memory demands and show step summaries (4.7.5); avoid walls of text (4.4.5; GOV.UK autism "don't create a wall of text"). — [W3C COGA](https://www.w3.org/TR/coga-usable/), [GOV.UK 2016](https://accessibility.blog.gov.uk/2016/09/02/dos-and-donts-on-designing-for-accessibility/)
- **Spelling tolerance [PRACTICE]:** GOV.UK dyslexia "don't rely on accurate spelling; offer autocorrect/suggestions." — [GOV.UK 2016](https://accessibility.blog.gov.uk/2016/09/02/dos-and-donts-on-designing-for-accessibility/)
- **Reminders [STANDARD]:** reminders only at user's request; personalise method; offer at end of task. — [W3C COGA 4.8.7](https://www.w3.org/TR/coga-usable/)

### Inferences
- Pacing: let the user choose between "one message at a time, tap to continue" and "all at once," and keep typing animations short, skippable and reduced under OS reduce-motion; a delay is a social cue (Gnewuch) but any artificial delay must never be a time pressure or hide text. This is an inference; no neurodivergent-specific pacing study was found.
- Quick replies vs free text: default to big tappable quick replies/tiles for check-ins (reduces typing/spelling burden and working memory), with free text and voice dictation as an always-available alternative that tolerates misspelling. Supported by COGA 4.5.8 and GOV.UK spelling advice, not by a head-to-head trial.
- Stability: quick-reply buttons and tiles should appear in a fixed position and not shift when new bubbles arrive or while the user is aiming (COGA 4.5.1); avoid auto-scrolling past a bubble the user hasn't read; after the user answers, collapse the tiles into a single "You chose: 😊 Happy" line rather than leaving mutable controls.
- Memory of prior answers: have Lexi echo what it knows ("Yesterday you chose 😴 Tired.") instead of asking the user to recall, and provide a short recap at the end of each check-in (COGA 4.7.5); allow a visible "Change my answer" for the last answer (COGA 4.5.5, 4.5.2).
- AI replies must be constrained by the same plain-language lint as scripted copy (section 3); the LLM should be told to output 1-3 short sentences, no idioms/sarcasm, consistent vocabulary, and no emoji unless emoji mode is on. Over-trust and masking findings argue for a clear "I'm a chatbot, not a person" line and avoiding advice-giving beyond journaling prompts (inference from the over-trust findings; not a clinical claim).
- Neurodivergent user inclusion: the scoping review's finding that most studies lack neurodivergent participants supports co-design/testing with dyslexic users for Lexi itself.

### Gaps
- No peer-reviewed study found on typing indicators, response pacing, message length, or quick replies for dyslexic/neurodivergent users; the search explicitly turned up none on pacing/chunking.
- The CHI 2026 paper was read via an aggregator/abstract; Xygkou et al. and the "diary" study via listings only; full methods and design recommendations not verified.
- Screen-reader/TTS behaviour for chat apps (aria-live for new messages, typing-indicator announcements) not researched.
- No sources found on voice input for dyslexic users within chatbots.

## 6. Navigation and memory: progress indicators in multi-step flows, going back, saving partial progress, avoiding time limits

### Takeaway
Standards are consistent: show step status, let users go back without losing work, autosave, avoid time limits (or make them very long/adjustable), and never require recall across steps. COGA 4.7.5 gives the concrete combination of "summary of prior steps + step indicator + easy way back + fix errors without full restart."

### Cited Findings
- **Step indicator, summary, back, error fixes [STANDARD]:** COGA 4.7.5 lists these four supports together; COGA 4.5.10 gives checkmarks on completed breadcrumb steps as feedback. — [W3C COGA 4.7.5, 4.5.10](https://www.w3.org/TR/coga-usable/)
- **Going back [STANDARD]:** back must be predictable and never delete user work (COGA 4.5.2). — [W3C COGA 4.5.2](https://www.w3.org/TR/coga-usable/)
- **Save as you go, tell time limits upfront [STANDARD]:** COGA 4.5.9; examples include a day to complete a task with option to extend, and a client-side timeout that keeps work in place on re-login; ask for sensitive data last. — [W3C COGA 4.5.9](https://www.w3.org/TR/coga-usable/)
- **Time limits [STANDARD]:** WCAG 2.2.1 (A) turn off / adjust (>= 10x) / extend (warning + >= 20 s, repeatable >= 10 times) except real-time/essential/over 20 hours; WCAG 2.2.6 (AAA) warn about inactivity data loss unless data kept over 20 hours. — [W3C 2.2.1](https://www.w3.org/WAI/WCAG22/Understanding/timing-adjustable.html), [W3C 2.2.6](https://www.w3.org/WAI/WCAG22/Understanding/timeouts.html)
- **No redundant entry (A) [STANDARD]:** 3.3.7. — [W3C What's new in 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/new-in-22/)
- **Short critical paths [STANDARD]:** keep processes to necessary steps; make optional steps separable. — [W3C COGA 4.6.2](https://www.w3.org/TR/coga-usable/)
- **Don't make users remember details from earlier pages [PRACTICE]:** give reminders/prompts instead (GOV.UK dyslexia). — [GOV.UK 2016](https://accessibility.blog.gov.uk/2016/09/02/dos-and-donts-on-designing-for-accessibility/)
- **WCAG 3 draft direction [STANDARD draft]:** Adequate time (adjustable/no/avoid/convey limits) and Prevent errors (submission status notification, data entry validation, error-prevention review). — [W3C WCAG 3.0 WD](https://www.w3.org/TR/wcag-3.0/)

### Inferences
- Lexi's check-ins should show a plain "Step 2 of 5" (words) plus dots or filled emoji markers, a visible Back button on every step, and autosave of each answer the moment it is tapped, so killing the app (RN backgrounding) never loses a half-finished check-in or journal entry.
- A "resume where you left off" bubble ("Want to finish your check-in? 😊") on return is a COGA 4.7.5/4.5.9 aligned pattern (inference), but keep it dismissible and non-guilt-inducing (see section 8).
- No session/inactivity timeouts for Lexi's UI; if auth tokens expire, preserve unsaved drafts locally for well over 20 hours.
- At the end of a check-in, show a one-screen summary the user can edit before saving (COGA 4.7.5/4.5.5).

### Gaps
- No empirical study found comparing progress-indicator styles for dyslexic or neurodivergent users in chat-style flows.
- COGA 4.2.4 "Make each step clear" detail text was not read.

## 7. Personalization profiles and onboarding (GPII, Fluid Preferences Framework, OS settings)

### Takeaway
The standards-aligned model is "set preferences once, reuse everywhere, easily reversible": COGA 4.9.4 and the GPII/Fluid lineage describe portable, user-controlled needs-and-preferences profiles; Apple's Assistive Access shows a cognitive-disability mode at OS level. For Lexi this means a short first-run preference setup (text size/spacing, emoji vs words, speed, voice) stored on-device and in the account, with a visible "change later" path.

### Cited Findings
- **COGA 4.9.4 [STANDARD]:** user-set font style, size, line height, margins, contrast; default stays readable; ability to roll back to a familiar interface; semantic markup lets agents swap symbol sets per user; store non-sensitive info for autofill; 4.9.3 simplification with "3 to 6 functions"; 4.9.1 "set once with the widest scope" as one definition of "easily available." — [W3C COGA 4.9](https://www.w3.org/TR/coga-usable/)
- **Fluid Preferences Framework [PRACTICE/open-source infrastructure]:** reusable schemas, APIs and UI building blocks for creating, persisting and integrating preference editors; event-driven API so adaptations react when preferences change. — [Fluid docs: Preferences Framework](https://fluidproject.atlassian.net/wiki/spaces/docs/pages/7079467/Preferences+Framework)
- **GPII / Preferences for Global Access [PRACTICE]:** goal of infrastructure for automatic personalization so devices adjust to the user "without requiring the users to figure out how to configure the features they need"; users store preferences securely in the cloud and take them across platforms/devices; privacy concern because preferences can reveal personal information; plan to use OAuth 2.0 for per-site approval. Fluid designs the GPII architecture and builds its core infrastructure; Cloud4All was an EC FP7 project. — [Fluid: GPII projects](https://fluidproject.org/projects), [Preferences for Global Access Architecture](https://fluidproject.atlassian.net/wiki/spaces/fluid/pages/11633696/Preferences+for+Global+Access+Architecture)
- **AccessForAll lineage [PRACTICE]:** began with Web4All's small needs-and-preferences file; Cloud4All chose AccessForAll as the basis for auto-personalization. — [Raising the Floor](https://raisingthefloor.org/our-approach-accessforall/)
- **Apple Assistive Access (iOS 17) [PRACTICE, secondary]:** streamlined system experience for cognitive disability with large controls, high-contrast buttons, large text labels, grid or row layouts; apps reduced to core functions. — [Perkins School](https://www.perkins.org/resource/apple-unveils-new-features-for-global-accessibility-awareness-day/), [9to5Mac](https://9to5mac.com/2023/05/16/apple-ios-17-accessibility-features/)
- **Spacing as a user setting [STANDARD + EVIDENCE]:** WCAG 1.4.12 plus Zorzi 2012 (section 3). — [W3C 1.4.12](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)
- **WCAG 3 draft [STANDARD draft]:** includes assistive-technology and user-settings support (2.12.1) and adjustable text colour with retained customizations (2.2.1). — [W3C WCAG 3.0 WD](https://www.w3.org/TR/wcag-3.0/)

### Inferences
- Onboarding should be 3-5 skippable choices with live preview and safe defaults: (1) text size, (2) spacing preset (normal/roomy/extra-roomy, mapping to the 1.4.12 values), (3) icons+words / words only, (4) message pace (tap to continue vs auto), (5) read-aloud on/off and voice. Everything else lives in Settings. Persist per device plus account; also respect OS-level font scaling/reduce-motion/dark mode (inference).
- Also personalise: emoji skin tone, background tint (cream vs white; BDA-style advice), font (system sans-serif by default), and notifications (COGA 4.6.1).
- Provide a "Reset to Lexi default" button and avoid hiding preference changes behind the Settings tab only; a quick access chip for text size/words-only inside Home is consistent with "reachable from every screen where it may be needed" (COGA 4.9.1).
- Settings should not reveal sensitive disability labels (the preference-profile privacy concern in the GPII documents); store preferences as UI settings, not as "I have dyslexia."

### Gaps
- No source found on Microsoft or Apple cross-device accessibility-settings sync (the assignment named "Microsoft/Apple accessibility settings sync"); only Assistive Access (device-level) was found, from secondary sources. Apple/Microsoft developer docs were not read.
- GPII/Fluid pages are marked draft/partly migrated; their status as maintained software in 2026 was not verified.
- No evidence on whether first-run preference screens improve outcomes for dyslexic users; the recommendation is design inference.

## 8. Gamification and streaks: help vs anxiety for neurodivergent users

### Takeaway
I found no peer-reviewed study specifically on streaks and anxiety in ADHD, autistic or dyslexic users; the evidence is practitioner opinion and anecdote that agrees streak-loss anxiety is real but disagrees about net effect. COGA's standards on reminders/interruptions point to opt-in, user-controlled motivation features.

### Cited Findings
- **Designer analysis [OPINION]:** Yu-kai Chou (Octalysis) argues streaks shift from accomplishment to loss avoidance around day 30 and recommends capped streaks and "recovery quests" rather than hard resets. — [Yu-kai Chou](https://yukaichou.com/?p=38981)
- **Anecdote/advocacy [OPINION]:** a developer of an ADHD wellness app with no streaks says streaks gave him anxiety and offers a "total active days" count; he reports about 75 users over 90 days and says retention data is too early. — [DEV Community](https://dev.to/nucleusos/adhd-support-app-no-streaks-why-gamification-hurts-more-than-it-helps-1ae0)
- **Commercial blog [OPINION, conflict of interest]:** a habit-tracker review site claims streak anxiety is the most common reason people abandon habit trackers and notes frequent reward feedback can suit dopamine-seeking ADHD users while busy interfaces overwhelm others; the site sells a no-streak app. — [Habitdoom](https://habitdoom.com/blog/streak-anxiety-habit-trackers)
- **Counter-anecdote [OPINION]:** a forum post says that for someone with ADHD and autism, streaks and gamification "can help me a lot to make something a habit." — [Lemmy post](https://lemmy.klein.ruhr/post/125890/586862)
- **Essay [OPINION]:** Institute of Network Cultures essay frames streak apps as an "anxious-preoccupied partner." — [Network Cultures, 19 Jan 2026](https://networkcultures.org/blog/2026/01/19/baby-please-dont-break-the-streak/) (title/summary only)
- **Relevant standards [STANDARD]:** reminders only at the user's request with user-personalised method (COGA 4.8.7); limit interruptions with notification settings (4.6.1); users control when content changes (4.9.1). — [W3C COGA](https://www.w3.org/TR/coga-usable/)
- **Journaling-specific:** I found no source on streaks in journaling apps for dyslexic users.

### Inferences
- If Lexi has or adds streaks: make them opt-in (off by default or chosen at onboarding), show cumulative counts ("12 days written 🌱") instead of consecutive-day loss framing, never show "you lost your streak," and add forgiveness (rest days). These are design inferences from opinion-level sources and from COGA's control principles, not tested findings.
- Notifications/reminders should be opt-in, user-scheduled, and quiet by default; a missed day should produce no guilt message.
- Because responses vary by person (Lemmy counter-anecdote), offer it as a choice rather than a default.
- Evaluate with a short in-app question or user test (anxiety/pressure ratings) before shipping any streak mechanic.

### Gaps
- No peer-reviewed evidence found (search did not surface any); a PubMed/Google Scholar search for "streak" + gamification + ADHD/autism/anxiety, or mental-health-app gamification reviews, is still needed.
- A Rotterdam thesis on gamification and ADHD symptoms (2017) appeared as a citation only; findings not retrieved.

## 9. Cross-cutting: likely gaps in Lexi and a checkable recommendation list

### Takeaway
Lexi's existing choices (short bubbles, big tiles with captions, 3 tabs, words-only mode) already match COGA/NN/g patterns. The likeliest gaps are in areas the brief doesn't mention: state persistence/undo, user-controlled pacing, consistent help, spacing/typography settings, emoji ambiguity governance, AI-reply linting, and optional (not default) motivation mechanics. Each item below states its basis and evidence class.

### Cited Findings
(see sections 1-8 for sources; each list item references them)

### Inferences (checkable recommendations; R-numbers for the report)
1. **R1 Bubble lint [PRACTICE + STANDARD]:** automated check on all scripted and AI-generated bubbles: <= 25 words per sentence (GOV.UK 2014, may be dated), target average <= 15-20 (Plain English Campaign via councils), <= 50 words per bubble (COGA 4.4.5), <= 3 sentences, no idioms/sarcasm (COGA 4.4.4/4.4.12; GOV.UK), no double negatives (4.4.3), consistent vocabulary (Inclusion Europe via e-include). Treat numbers as conventions.
2. **R2 Visible label everywhere [STANDARD/PRACTICE]:** every emoji/icon (tabs, tiles, pills) has an always-visible word (NN/g 2014; COGA 4.2.7).
3. **R3 Yes/No pills [STANDARD + inference]:** show words "Yes"/"No" on 👍🏽/👎🏽; phrase prompts so Yes is the plain affirmative; one meaning per icon (COGA 4.2.7, 4.4.3).
4. **R4 Emoji governance [EVIDENCE + STANDARD]:** fixed bundled tile art (or user-selectable symbol set) to avoid cross-platform drift (Miller 2016; COGA 4.9.4); a single emoji at start/end of a bubble rather than inline; words-only mode strips emoji from AI replies too.
5. **R5 Icon testing [PRACTICE]:** test recognisability and 2-week memorability for the three tab glyphs (NN/g); 🏡/📖 are hypotheses to test.
6. **R6 User-controlled pace [STANDARD]:** "tap for next message" option; skippable short typing animation; respect reduce-motion; no auto-advance or timed prompts (COGA 4.9.1, 4.6.1; WCAG 2.2.1).
7. **R7 Stable controls [STANDARD]:** quick-reply tiles/pills do not move or reflow as new bubbles arrive (COGA 4.5.1); targets >= 24x24 CSS px with spacing between Yes and No (WCAG 2.5.8; COGA 4.2.5).
8. **R8 Back, undo, edit [STANDARD]:** Back on every step; "Change my answer" for the previous answer; edit/delete past journal entries with confirmation stating the result (COGA 4.5.2, 4.5.5, 4.8.3).
9. **R9 Autosave and no timeouts [STANDARD]:** persist each answer and draft immediately; resume prompt; no inactivity expiry under 20 hours (COGA 4.5.9; WCAG 2.2.1/2.2.6).
10. **R10 Progress + recap [STANDARD]:** words+dots step indicator and end-of-flow summary (COGA 4.7.5, 4.5.10).
11. **R11 No redundant questions [STANDARD]:** prefill/echo previous answers and never re-ask in the same flow (WCAG 3.3.7; GOV.UK "don't make users remember").
12. **R12 Consistent help [STANDARD]:** same-place "Need help?" on every screen, including inside Journal/Settings (WCAG 3.2.6; COGA 4.8.5); add human/crisis resource route appropriate to a journaling app (COGA 4.8.1, 4.5.11 titles only; scope decision for the team).
13. **R13 Spelling tolerance [PRACTICE]:** free text and journal input accept misspellings, offer suggestions rather than errors, support voice dictation (GOV.UK 2016; COGA 4.5.8).
14. **R14 Text and spacing settings [STANDARD + EVIDENCE]:** user-adjustable size, line/letter/word spacing (including an "extra roomy" preset), left-aligned, no justification/italics/all-caps, tinted background, system sans-serif; web build passes the 1.4.12 override test (WCAG 1.4.12; Zorzi 2012; BDA via secondary sources).
15. **R15 Onboarding preferences [STANDARD + PRACTICE]:** 3-5 first-run choices, reversible, saved once and reused across web/native; reachable from Home (COGA 4.9.1/4.9.4; GPII/Fluid).
16. **R16 Authentication [STANDARD]:** if accounts exist, no memory/puzzle-only login; allow password managers, magic link or biometrics (WCAG 3.3.8; COGA 4.7.1-4.7.3 titles).
17. **R17 Streaks opt-in [OPINION + STANDARD]:** no default streaks; cumulative counts; no loss framing; user-scheduled reminders only (COGA 4.8.7, 4.6.1; Chou).
18. **R18 AI transparency and scope [EVIDENCE-adjacent]:** state "I'm a chatbot" in plain words; keep to journaling prompts; avoid advice beyond scope (over-trust findings).
19. **R19 Test with dyslexic users [STANDARD + PRACTICE]:** include dyslexic and other neurodivergent testers (COGA Section 5; Inclusion Europe testing rule; Xu et al. 2025 gap of participation).

### Gaps
- All recommendations above assume the brief accurately describes Lexi; no codebase audit was done, so each should be verified against the actual UI.
- Numeric thresholds (words per sentence, emoji per bubble, step counts) lack trial-based support for dyslexic chat users.
